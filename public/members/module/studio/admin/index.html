Administracja

Zarządzanie platformą

Zarządzaj uczestnikami, płatnościami, zgłoszeniami i zawartością strony kursu.

i

Ustaw stronę powitalną i miejsce publikacji JSON w repozytorium. Dostawcę GitHub lub Gitea określa GIT_PROVIDER. Publikację w repozytorium lub Netlify Blobs wybierasz w Landing Builderze. Logowanie, panel i kurs pozostają w tej aplikacji. Aktywne źródło i cennik korzystają z cache ograniczającego wywołania Functions.

Strona powitalna

Włączone: strona główna przekieruje na podany adres HTTPS. Wyłączone: działa lokalny landing NextMed. Nie osadzamy obcej strony w ramce.

Repozytorium musi być publiczne. Token wybranego dostawcy potrzebuje uprawnień do docelowego repozytorium oraz repozytorium assetów wskazanego w ENV. Jeśli plik nie istnieje, skopiujemy aktualną publikację; istniejącego landingu nie nadpiszemy.

Wpisany token repozytorium jest przesyłany tylko podczas zapisu lub testu. Nie jest trwale zapisywany w przeglądarce, nie wraca w odpowiedzi API ani nie trafia do kursantów. Ręczna konfiguracja awaryjna i zasady tokenu
  1. Utwórz jedno lub kilka prywatnych repozytoriów z folderami lessons i prompts.
  2. Wybierz dostawcę przez GIT_PROVIDER. W Gitea utwórz token z write:repository na koncie mającym dostęp tylko do potrzebnych repozytoriów. W GitHub użyj fine-grained tokenu ograniczonego do wybranych repozytoriów z Contents: Read and write.
  3. Na Free dodaj token ręcznie jako site-level ENV w Project configuration → Environment variables. Secrets Controller i automatyczne oznaczenie tokenu jako sekretu są dostępne od planu Personal.
  4. Osobny zakres Functions jest dostępny na Pro/Enterprise. Na Free/Personal zmienne mają domyślny zakres wszystkich usług.
  5. Dla kilku repozytoriów ustaw GITEA_CONTENT_REPOSITORIES lub GITHUB_CONTENT_REPOSITORIES. Instrukcje: GITEA_SETUP.md i README. Po zmianie ENV uruchom nowy deploy Functions.

Konfigurator repozytoriów

Prywatne repozytoria materiałów

Dodaj maksymalnie 20 repozytoriów. Pusty token zachowuje istniejący sekret lub korzysta ze zmiennej utworzonej ręcznie.

Netlify: automatyczne sekrety PAT — Personal/Pro/Enterprise; osobny zakres Functions — Pro/Enterprise. Na Free najpierw utwórz wskazaną zmienną tokenu ręcznie, wykonaj deploy, a następnie zapisz tutaj konfigurację z pustym polem tokenu.

Wymagane jednorazowo: NETLIFY_API_TOKEN i automatyczne SITE_ID. Zapis sekretu jest zawsze fail-closed: jeśli Netlify nie może użyć Secrets Controller, PAT nie zostanie zapisany jako zwykła zmienna. Po zmianie ENV wykonaj deploy i poczekaj na jego zakończenie przed kolejną edycją.
